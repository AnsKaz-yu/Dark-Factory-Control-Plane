# opencode-harness-viz

OpenCode-плагин: интерактивная HTML-визуализация harness проекта.

## Что визуализирует

1. **Loop разработки** — DMTools оркестрация → старт фичи (US/B/F/U) → RED → реализация
   (opencode) → GREEN → гейты качества → обновление C4 → хронология → коммит (G6) → CI Jenkins → ↺.
2. **Гейты качества** (детерминированные) — **G1–G16**: C4, TDD, CRAP, oracle, build/lint,
   чистота публикации, покрытие, безопасность/лицензии, детерминизм, численная верификация,
   бенчмарки, архитектура, oracle-покрытие, мутации, фаззинг, безопасность памяти.
3. **Точки контроля** — детерминированные (авто, G1–G16) и человеческие (H1–H6).
4. **Инструменты** — по категориям (оркестрация, документация, качество, CI/CD, toolchain).
5. **Метрики** — формула CRAP (порог 30 / цель 15), пороги точности vs эталон.

## Источник данных

`harness-model.json` в проекте (авто-поиск). Модель отделена от рендера — при эволюции
harness обновляется модель, визуализация перегенерируется.

## Фактическое состояние («как есть и работает»)

Визуализация отражает **реальное рабочее состояние**, а не только записи документации.
Каждый гейт/шаг loop/инструмент/точка контроля может иметь поля:
- `status` — фактический статус:
  - `verified` — работает, проверено реальным прогоном (зелёный);
  - `partial` — работает частично / есть ограничения (жёлтый);
  - `conditional` — реализован, но skip до появления кода/данных Phase 2 (голубой);
  - `vacuous` — формально проходит, но реально ничего не проверяет (оранжевый);
  - `stub` — заглушка / hardcoded skip (красный);
  - `not-enforced` — описан, но фактически не применяется (красный).
- `note` — пояснение «Фактически: …» (что проверено / ограничения / чего не хватает).

На уровне модели: `asOf` (дата аудита) и `realityNote` (пояснение к сводке).
Рендер добавляет цветные бейджи статуса, строку «Фактически», **баннер сводки** (счётчики
по статусам среди гейтов) и легенду. Статусы заполняются по результатам аудита/прогонов,
а не копируются из деклараций.

## Коммит в репозиторий (обязательно)

HTML-визуализация **коммитится в репозиторий** (`<harness>/harness-viz.html`, корень, не
gitignore) и **обновляется при каждом изменении harness**:
1. Изменился harness (гейты/инструменты/loop/точки контроля) → обновить `harness-model.json`.
2. Перегенерировать: `harness_visualize` (или `/harness-viz`, или `node generate-viz.mjs`).
3. Закоммитить `harness-viz.html` + `harness-model.json` вместе с изменением harness.

Так визуализация всегда отражает актуальное состояние harness в истории репозитория.

## Использование

- Команда `/harness-viz` или инструмент `harness_visualize`.
- Standalone: `node generate-viz.mjs <model.json> <out.html>`.

Self-contained HTML (inline CSS/JS, без внешних зависимостей), dark theme, интерактивная
подсветка связанных гейтов.
